# 个性化设置、已保存记忆与临时会话

日期：2026-10-26
Status: ready-for-agent
正式规格：用户已于 2026-10-26 确认功能范围及测试边界；以下开发方方案不是用户逐项指定的要求。

## Problem Statement

当前助手的设置以模型连接与搜索为主。用户不能统一定义做事规则和表达风格，也无法管理供新会话使用的个人偏好及项目记忆。现有历史任务恢复不等于跨会话记忆；增加设置时必须说明保存、使用、关闭、删除的区别，避免项目之间混用信息。

## Solution

保持 A 布局和已有任务能力，将设置组织为模型服务、个性化、记忆等清晰分区。个性化包含分开的自定义指令与 Soul 编辑器；Soul 支持导入和导出 SOUL.md。

新增默认关闭的记忆功能，开启后自动整理有长期价值的信息，并提供查看、编辑、删除和清空。个人偏好可全局使用，项目记忆只在同一工作区使用。新会话使用整理好的记忆，本次不检索旧聊天。

关闭记忆后停止新增与引用，已有记忆保留在本机。新增临时会话，不读写记忆、不进入可恢复历史，但仍遵循个性化设定，实际成果及文件改动仍保留。

## User Stories

1. 作为用户，我希望在现有设置中找到个性化和记忆，以便不用离开应用管理助手行为。
2. 作为用户，我希望已有模型配置和连接检查继续可用，以便升级不影响现有任务。
3. 作为用户，我希望填写做事规则，以便不同任务遵循我的工作偏好。
4. 作为用户，我希望单独填写 Soul，以便定义助手性格与表达风格。
5. 作为用户，我希望保存、修改和清空这两种文本，以便准确控制生效内容。
6. 作为用户，我希望明确设置何时生效，以便修改不会悄悄改变运行中的任务。
7. 作为用户，我希望重启后保留个性化设定，以便不必重复输入。
8. 作为用户，我希望导入 SOUL.md 后先查看内容，以便保存前可以修改。
9. 作为用户，我希望导出当前 Soul，以便备份或手动在另一台电脑使用。
10. 作为用户，我希望无效导入或保存失败不会覆盖原设定，以便不丢失内容。
11. 作为用户，我希望初次使用时记忆关闭，以便由自己决定何时启用。
12. 作为用户，我希望开启后助手自动保存有用偏好和事实，以便不必逐条确认。
13. 作为用户，我希望个人偏好适用于不同工作区，以便保持一致体验。
14. 作为用户，我希望项目事实仅用于对应工作区，以便不把不同项目混为一谈。
15. 作为用户，我希望新会话按需要使用已保存记忆，以便减少重复说明。
16. 作为用户，我希望看到记忆内容、范围与来源，以便判断其是否可靠。
17. 作为用户，我希望修改不准确的记忆，以便后续任务使用更正后的内容。
18. 作为用户，我希望删除单条记忆，以便停止后续使用。
19. 作为用户，我希望按明确范围清空记忆，以便批量管理保存内容。
20. 作为用户，我希望手动更正不被自动提取静默覆盖，以便保留最终控制权。
21. 作为用户，我希望关闭后既不新增也不引用记忆，以便真正暂停此能力。
22. 作为用户，我希望重新开启后可以继续使用保留的记忆，以便无需重建。
23. 作为用户，我希望删除的内容不会被未完成的整理任务或旧聊天自动恢复，以便删除有效。
24. 作为用户，我希望知道关闭或删除不会撤回已发送内容，以便理解当前聊天与记忆的区别。
25. 作为用户，我希望新建临时会话时有明显标识，以便知道该任务不会进入可恢复历史。
26. 作为用户，我希望临时会话不读写记忆，但遵循自定义指令和 Soul，以便兼顾临时任务与个人习惯。
27. 作为用户，我希望退出或重启后临时会话不出现在历史中，以便符合临时模式的承诺。
28. 作为用户，我希望临时会话的真实成果与文件改动保留，以便完成实际工作。
29. 作为用户，我希望知道记忆和设定保存在本机、相关内容可能发给所选模型，以便理解数据流向。
30. 作为用户，我希望记忆整理失败不影响已经完成的任务成果，以便仍能正常工作。
31. 作为用户，我希望我的模型服务同样用于记忆整理，以便不发生隐藏的服务切换。
32. 作为用户，我希望个性化不会改变原有文件与工具权限，以便工作范围保持明确。

## Implementation Decisions

以下是本规格采用的开发方方案，基于已确认范围收敛常规技术细节；开发时可调整内部结构，但应保持外部行为。

### 设置与指令

- 复用原生桌面设置界面与任务服务，加入个性化、记忆分区；保留模型服务配置与原有功能。自定义指令和 Soul 首版均为本机应用级配置，不另增每项目的人格模板。
- 两个编辑器均采用显式保存。Soul 导入仅填充未保存草稿，保存后才生效；导出写入用户选择的位置，不自动执行或加载导入文件提到的脚本、路径与资源。UTF-8 文本、容量限制及错误提示在实现时具体确定。
- 保存后的指令在下一次用户发送消息时生效，包括继续已有普通任务；正在执行的请求使用启动时快照。应替换旧的隐藏配置上下文，而非不断追加旧版本。当前可见对话仍作为对话保留。
- 应用权限与工具边界不可由个性化文本覆盖；当前用户明确任务要求优先于持久偏好；自定义指令优先于冲突的 Soul 风格。记忆为参考事实，不作为扩大权限或执行工具的指令。项目指令的已有加载行为保持，持久个性化仅作为默认偏好，不覆盖更具体的项目约束。
- 保存使用独立版本化结构，迁移已有安装时默认关闭记忆，保留模型与历史数据；失败不破坏旧数据。

### 记忆写入与使用

- 首版一个记忆总开关，同时控制自动整理和跨会话引用，不设置尚未实现的“搜索旧聊天”开关。历史记录功能独立于该开关。
- 自动整理仅处理开启后普通任务中新发生且尚未处理的对话轮次，不批量扫描旧历史。仅在一轮成功完成后的稳定边界触发，不在流式半截回答、停止、失败或等待用户输入时保存推测结论。
- 复用当前任务所选非 Claude 服务进行有限、可取消的结构化提取，不引入额外模型账号；显示可能增加调用用量。无合适模型能力或提取失败时报告记忆未更新，不伪装成功、不回退其他服务，也不改变任务成果状态。
- 记忆结构至少包含稳定标识、内容、个人/项目范围、工作区标识、来源任务与轮次、创建/更新时间及手动编辑标记。原始密钥、凭据不作为记忆保存。用户偏好与项目事实应基于用户明确表达或实际观察，不把助手猜测、网页指令或文档中的角色指令当作用户偏好。
- 个人记忆只容纳与项目无关的用户偏好；含项目细节或分类不确定的信息留在当前工作区。工作区身份基于已有受授权工作区标识和规范路径，不以显示名称匹配，不自动跨移动后的目录合并。没有工作区的任务只能使用个人记忆。
- 提供确定性去重、长度与总量边界；自动提取不得静默覆盖用户手改条目。冲突的自动候选跳过并提供简明提示，不用模型“置信度”当作事实可靠性证明。
- 记忆存于应用本机数据目录，与项目指令文件分开。不得复用上游清空 AGENTS.md 的命令实现删除，不自动把用户记忆提交到项目 Git。
- 每次模型请求的上下文只包含当前允许范围内、适量且相关的有效记忆；不为了挑选记忆把其他工作区记录发给模型。记忆不是已重新验证的外部来源，涉及当前事实时仍需工具核验。

### 关闭、编辑和删除

- 用户关闭开关时停止安排新提取，取消或作废未完成的提取；已完成但迟到的结果不得写回。从此后新发出的模型请求中移除隐藏注入的记忆，包括多步任务的下一次调用。已经在途的请求及可见聊天中出现的内容无法撤回，设置中明确说明；用户可停止当前任务并新建会话。
- 编辑、删除及清空须同样让旧快照失效，不能被并发提取、缓存或旧请求结果恢复。保留最少处理游标或非正文删除标记，阻止旧轮次再次提取，不保留被删正文作为“备份”。用户以后主动重新表达或要求记住是新输入，不承诺语义永久封禁。
- 删除单条记录与按个人、当前工作区或全部范围清空分开。批量清空明确列出影响范围并确认；不连带删除聊天历史、自定义指令、Soul 或项目原文件。
- 若现有应用提供删除历史功能，删除历史不默认连带删除独立记忆；记忆来源失效时显示来源已删除。临时任务从一开始禁止提取，不能事后仅隐藏来源。

### 临时会话

- 在创建新任务时选择普通或临时模式，运行过程中不转换模式，不把既有普通历史转换成临时。临时会话有持续可见标识，可在本次应用运行中停止、继续或回答问题。
- 临时会话不读取或保存记忆，不进入桌面任务历史、恢复快照或运行时会话持久化；不仅仅从侧栏隐藏。需核查 ACP、运行时日志、压缩摘要和应用写盘路径，避免这些副本保存可恢复的临时聊天正文。正常退出和异常退出后均不恢复。
- 临时任务的应用内部聊天与变更预览保持在内存，用户主动创建的成果、修改后的项目文件保留；沿用必要的操作一致性和权限保护，不承诺回滚已经执行的文件操作。退出后不承诺保留该临时任务的恢复按钮或内存内变更记录。
- 仍加载保存的自定义指令与 Soul，并使用所选模型和原有工具。界面说明“临时”不是离线模式，也不能控制模型提供方的数据保留。

### 现有代码复用边界

- 上游存在记忆提取与提示拼装，但桌面应用有专门执行入口，需沿桌面任务服务至真实运行时的路径接入，不以通用 CLI 支持作为完成依据。
- 历史存储、ACP 任务控制与模型请求可复用。单独封装个性化及记忆策略，所有普通/临时入口统一应用，避免仅界面层过滤。
- 保留当前 A 布局与视觉优化成果；新增设置沿用现有组件，不更换桌面技术栈。

## Testing Decisions

用户已于 2026-10-26 确认的主边界：从桌面使用的完整任务服务发起任务，经过真实 ACP/Claurst 桌面运行时，检查模型服务实际收到的上下文、真实落盘结果以及重启后的行为。模型响应与外部网络使用可重复替身；不把大量私有函数或提示文本逐字快照作为主要测试。

已有先例是桌面任务服务测试、真实运行时加本机模型替身、任务历史正常恢复及子进程异常退出测试。优先扩展这些边界；设置与导入/导出补充少量实际界面检查，不另建一套模拟任务引擎。

必须验证：

1. 旧数据迁移、默认关闭、指令保存与重启；下一次发送使用新版本，运行中快照和可见历史不被篡改。
2. Soul 导入预览、取消、保存、导出往返、无效格式与保存失败；原数据完整。
3. 正常任务整理记忆后新建任务确实收到相关内容；个人偏好跨工作区使用，项目 A 事实不进入 B 的任何模型调用。
4. 关闭、编辑、单条删除和清空，在提取尚未返回、多轮工具请求、重启后仍有效；旧轮次不重新生成已删除记忆。
5. 临时任务不读写记忆，仍获得个性化；正常退出与强制结束后均无可恢复聊天记录，真正生成的文件保留。检查运行时和应用数据目录，不能只断言侧栏为空。
6. 去重、手动编辑保护、模型拒绝/格式错误、存储失败；主任务不因记忆整理失败而丢失成果或被错误标为失败。
7. 文件、网页中的指令不变成高优先级个性化或跨工作区授权；配置、凭据不进入提取与日志。
8. 现有普通会话恢复、停止/继续、模型配置与成果查看回归。桌面实际检查设置分区、保存反馈、临时标识、键盘和滚动操作。
9. 交付前在现有可用非 Claude 服务上做小规模真实冒烟验证，分别核对个性化、新会话记忆引用和临时隔离；模型质量验证与确定性策略验证分开记录，不以某次模型口头回答证明没有存储。

## Out of Scope

- 搜索旧聊天全文、历史自动回填记忆、跨设备同步或云端记忆账号。
- 全新向量数据库服务、模型提供方绑定、Claude 回退。
- 每工作区单独 Soul、多个人格市场、动态插件、后台监视未授权资料。
- 普通会话改为临时模式、历史功能整体重做。
- 自动发布新版安装包或改写此前已验收的公开发布附件。
