# 使用个性化、记忆与临时会话

打开“模型设置”（Command-,），选择“个性化”或“记忆”。原有模型服务配置与连接检查仍在“模型服务”分区。

## 个性化

自定义指令适合长期做事规则；Soul 适合语气、性格和表达风格。两项分别编辑并显式保存，每项上限 32 KiB UTF-8 文本。保存后下一次发送生效，继续旧任务也会使用新设定；正在执行的一轮保持原设定。当前任务和具体项目约束优先，个性化不能扩大工具权限。

导入 SOUL.md 只填入草稿，确认内容后保存才生效。导出写入当前已保存的 Soul，不包含未保存草稿。文件里的脚本、链接和路径不会因导入而执行或自动加载。清空草稿后仍需保存。

## 记忆

默认关闭。开启后，普通任务成功完成的新轮次由当前所选模型整理，可能增加调用用量；不回填旧聊天。界面会提示正在整理、完成或未更新，整理失败不改变已经完成的任务成果。

是否保存成功，以桌面的整理提示和设置中的实际记录为准。模型的聊天回复可能不准确地描述保存状态；自动记忆不要求模型另行写入项目文件。

首版只将明确通用的回答语言、详略和格式偏好共享到其他工作区，例如“我偏好简洁回答”“我偏好用中文回答”。不明确通用的表达保留在当前工作区；没有用户工作区时不保存这类项目候选。个人/项目记忆共用一个开关，设置中能看到内容、范围、来源与更新时间。

项目按规范路径及目录身份识别，同名目录互不继承；移动目录后不自动合并旧记忆。每条内容最多 1024 字节，总计最多 500 条，每次请求最多选用当前允许范围的 16 条、8 KiB 内容；记忆是参考，不代表已核实的当前事实。

编辑后立即影响后续请求，自动整理会跳过与手动更正主题冲突的候选。可删除单条，或经确认清空个人、当前工作区、全部记忆。关闭只暂停新增和使用，保留已有记录；重新开启可继续使用。删除、编辑和关闭均使未完成的旧整理失效。用户以后主动重新表达属于新输入。

聊天历史、自定义指令、Soul 和项目文件不随记忆清空。已经发送给服务的内容及可见对话无法撤回；如需停止当前上下文继续使用，可停止任务并新建会话。

## 临时会话

在侧栏或任务菜单选择“临时会话”。模式创建时确定，现有普通任务不能切换为临时。顶部和侧栏始终显示标识。

临时会话使用自定义指令、Soul、所选模型和原有工具，但不读写记忆，不保存聊天历史、会话摘要或恢复快照。本次运行内可以停止、继续、回答问题、查看修改及恢复；退出后这些对话和预览不会恢复。

实际新建或修改的文件会保留，临时模式不会回滚操作。必要内容仍发送给所选模型，模型提供方的数据保留由其规则决定。

当前真实服务验收状态见 [验收记录](../build/verification-personalization-memory.md)。
